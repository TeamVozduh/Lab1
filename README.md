# Лабораторная работа № 1

## «Контракты в интерфейсе»

### Описание проекта

Настольное приложение для управления операциями каршеринга, разработанное на C# с использованием WPF и .NET 8.

**Цель работы** — изучить принципы формулирования контрактов операций в виде предусловий (Pre) и постусловий (Post), а также научиться отображать результаты их проверки непосредственно в пользовательском интерфейсе.

### Функциональные возможности

Приложение предназначено для демонстрации операций, связанных с использованием автомобилей в каршеринге.

Основные возможности:

* ввод параметров для выполнения операций;
* проверка предусловий перед выполнением операции;
* проверка постусловий после выполнения операции;
* отображение результатов проверок с помощью цветовых индикаторов;
* просмотр контрактов операций, включая предусловия, постусловия, эффекты и исключения;
* обработка корректных и некорректных входных данных.

### Контракты операций

Для каждой операции определяются следующие условия:

* **Pre (предусловие)** — требования к входным данным и состоянию системы перед выполнением операции.
* **Post (постусловие)** — требования к результату после выполнения операции.
* **Эффекты и исключения** — изменения состояния системы и ситуации, при которых операция не может быть выполнена.

Результаты проверок отображаются в пользовательском интерфейсе:

* 🟢 Зелёный индикатор — условие выполнено.
* 🔴 Красный индикатор — условие не выполнено.

### Используемые технологии

* **C#** — язык программирования.
* **.NET 8** — платформа разработки.
* **WPF** — технология создания настольного пользовательского интерфейса.
* **MVVM** — архитектурный подход к организации приложения.
* **xUnit** — средство модульного тестирования.

### Проверка и тестирование

Для проверки корректности работы приложения используются предусловия и постусловия. Перед выполнением операций проверяются допустимость входных данных и необходимые условия. После выполнения проверяется соответствие результата заданному контракту.

Модульные тесты предназначены для проверки бизнес-логики, обработки граничных значений и поведения операций при корректных и некорректных входных данных.

### Сборка и запуск

Для сборки и запуска проекта необходим установленный .NET 8 SDK.

1. Клонируйте репозиторий:

   ```bash
   git clone https://github.com/TeamVozduh/Lab1.git
   ```

2. Перейдите в каталог проекта:

   ```bash
   cd Lab1
   ```

3. Восстановите зависимости:

   ```bash
   dotnet restore Lab1.sln
   ```

4. Соберите решение:

   ```bash
   dotnet build Lab1.sln
   ```

5. Запустите модульные тесты:

   ```bash
   dotnet test Lab1.sln
   ```

Для запуска приложения откройте `Lab1.sln` в Visual Studio, выберите проект `Lab1` в качестве запускаемого и нажмите **F5**.

# Лабораторная работа № 2

## Калькулятор слабейшего предусловия

Вкладка **«Конструктор фрагмента»** вычисляет слабейшее предусловие `wp(S, Post)` —
условие, которое должно выполняться **до** фрагмента `S`, чтобы после его выполнения
выполнялась заданная цель `Post`. Расчёт символьный: приложение разбирает текст
программы и преобразует логические выражения, а не запускает введённый фрагмент.

### Как пользоваться вкладкой

1. Введите цель в поле **«Цель (Post)»**. Под ним появится пояснение условия словами.
2. Введите программу без циклов в поле **«Код фрагмента»** или выберите один из
   встроенных примеров.
3. Нажмите **«Рассчитать wp»**. Справа появятся шаги обратного расчёта, итоговая
   формула и её словесное описание.
4. Нажмите **«Показать триаду»**, чтобы вывести `{ wp } S { Post }` и пояснение.

Изменение программы или цели сбрасывает предыдущий результат. Ошибки синтаксиса
показываются в поле трейса с указанием позиции во входном тексте.

### Поддерживаемый язык

```text
x := x + 10;
if (x >= 0) { y := abs(x); } else { y := -x; }
```

Программа состоит из присваиваний, последовательностей операторов через `;` и
ветвлений `if (...) { ... } else { ... }`. Ветка `else` обязательна; циклы не
поддерживаются. В арифметике доступны `+`, `-`, `*`, `/`, `abs()` и `sqrt()`.
В условиях доступны сравнения `=`, `==`, `!=`, `<`, `<=`, `>`, `>=`, отрицание `!`,
логические `&&` и `||`, а также скобки. Десятичные числа записываются с точкой.

### Как читать результат

Движок переносит `Post` через операторы **с конца к началу**. Для присваивания
`x := e` он заменяет `x` выражением `e` в текущей цели. Для `if` отдельно получает
условие каждой ветки и объединяет их с проверкой условия ветвления. В трейсе
каждый шаг показывает, через какой оператор прошёл расчёт и какое условие
требуется перед ним.

Если выражение может быть не определено, в `wp` добавляется ограничение:
для `a / b` требуется `b != 0`, для `sqrt(a)` — `a >= 0`. Логические `&&` и `||`
учитывают вычисление по короткой схеме: правая часть должна быть определена
только тогда, когда до неё доходит вычисление. Упрощение сворачивает очевидные
константы и простые сравнения, но не является универсальным решателем уравнений.

Например, для программы

```text
y := x + 1;
x := x + 10;
```

и цели `y = x - 9 && x > 15` итоговое предусловие — `x > 5`. Сначала цель
переносится через второе присваивание, затем через первое. Этот сценарий,
**максимум из двух** и **квадратное уравнение с ветвлением по дискриминанту**
доступны как пресеты.

### Где находится реализация

* `Lab1/ClassLibrary/Wp/WpSyntax.cs` — токенизация и разбор программы и `Post` в
  деревья выражений и операторов.
* `Lab1/ClassLibrary/Wp/WpLogic.cs` — подстановка, условия определённости,
  упрощение и вывод формул словами.
* `Lab1/ClassLibrary/Wp/WpEngine.cs` — обратный проход по программе, трейс и
  итоговая триада Хоара.
* `Lab1/Lab1/MainWindow.xaml` и `MainWindow.xaml.cs` — поля ввода, пресеты и
  отображение результата, полученного из библиотеки.
* `Lab1/UnitTests/Wp*Tests.cs` — проверки разбора, логических правил и движка.

В текущей структуре репозитория решение находится в каталоге `Lab1/`. Поэтому
из корня репозитория приложение можно собрать, проверить и запустить так:

```bash
dotnet restore Lab1/Lab1.sln
dotnet build Lab1/Lab1.sln
dotnet test Lab1/Lab1.sln
dotnet run --project Lab1/Lab1/Lab1.csproj
```
